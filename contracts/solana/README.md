# Bonded on Solana

Three Anchor programs, mirroring the EVM contracts (see `docs/SPECIFICATION.md` Section 7):

- `bonded_registry`: agents and their attester-signed scores.
- `bonded_vault`: checks every agent call, keeps the breach log, freezes on a breach.
- `bonded_cover`: underwriting pool, operator bonds, signed quotes and parametric claims.

Two supporting crates:

- `crates/bonded_client`: addresses and instruction builders for all three programs. The tests, the devnet runner and the keeper build instructions with it, so the LiteSVM tests (`tests/flow.rs`) check the same code that runs on devnet.
- `crates/bonded_devnet`: the `bonded-devnet` command, which sets up and exercises the programs on devnet.

## Build and test

From the repository root:

```bash
pnpm solana:test
```

This builds the programs and runs the tests on LiteSVM.

The runner's configuration and network regression checks run without sending transactions, from `contracts/solana`:

```bash
cargo test -p bonded_devnet
```

## Devnet

The program ids come from keypairs in `target/deploy/`, which stay out of git (ADR-011, section 6). Deploy with the matching keypairs, never with `--ignore-keys`.

**1. Deploy**, from `contracts/solana`, with the deployer wallet (`~/.config/solana/id.json`) holding devnet SOL. `--max-len` sizes each program to its binary, which roughly halves the rent; an upgrade to a larger binary first needs `solana program extend`.

```bash
for p in bonded_registry bonded_vault bonded_cover; do solana program deploy -u devnet --program-id target/deploy/$p-keypair.json --max-len $(stat -f%z target/deploy/$p.so) target/deploy/$p.so; done
```

The deployer becomes each program's upgrade authority, which the programs require to initialize.

**2. Set up**, once and safe to repeat: a test-USD mint, the three programs initialized, test accounts funded and the pool seeded with 1,000,000 test USD. It writes `deployments/devnet.json`.

```bash
cargo run -p bonded_devnet -- setup
```

Both commands verify the RPC's genesis hash before sending transactions. Private devnet RPC URLs work regardless of their hostname. A local validator must use a loopback URL; mainnet and testnet are refused even through a local proxy.

Setup checks the deployed programs, existing configuration and test mint before funding accounts or minting tokens. Keep the original test keys: if an attester or authority does not match, restore the matching keys or point `BONDED_SOLANA_KEYS` and `SOLANA_KEYPAIR` at them. Generating new keys does not reset an existing deployment. If the pool has no assets but still has shares outstanding, setup stops before minting; it does not automatically recapitalize the pool.

**3. Run the end-to-end flow.** Each run registers a new agent, posts a signed score, creates a vault holding 50,000, bonds 500, buys 20,000 of cover with a signed quote, has the agent send 1,000 out (a breach), and files the claim. It checks the vault froze, that 900 came back (the 10% deductible), the bond paid first and the pool the rest, and prints an explorer link for every transaction.

```bash
cargo run -p bonded_devnet -- e2e ../../docs/progress/evidence/solana-devnet-e2e.json
```

The test keys (attester, operator, agent, underwriter, mint) are created on first use in `~/.config/bonded/solana-devnet/`, outside the repository. `SOLANA_RPC_URL=http://127.0.0.1:8899` runs the same commands against a local validator, for a rehearsal.

## TypeScript client and keeper

- **`packages/solana` (`@bonded/solana`):** the TypeScript twin of `bonded_client`.
  - Program ids, addresses, and account decoding and instructions, all built from the programs' IDLs (`src/idls.ts`, generated by `pnpm --filter @bonded/solana idls` after `pnpm solana:build`).
  - `idls:check` fails if the committed IDLs are out of date.
  - A test checks it derives the same pool address the Rust runner recorded on devnet.
- **`SolanaKeeper` (`apps/keeper/src/solana.ts`):** files claims for covered breaches, like the EVM keeper.
  - It is stateless: each vault's breach log records what is claimed, and the cover program refuses a second claim.
  - It applies the program's own rules before sending anything: the policy is active and its claim window open, and each breach is unclaimed, not blocked, lost something and happened during the policy.
  - It publishes `solana.claim.paid` or `solana.claim.failed` events.
  - The keeper role runs it every 15 seconds when `SOLANA_RPC_URL` and `SOLANA_KEEPER_KEY` are set.

To check the keeper end to end on a local validator:
1. Deploy the programs and run `setup` (see "Devnet", with `SOLANA_RPC_URL=http://127.0.0.1:8899`).
2. Leave a covered breach unclaimed:

```bash
cargo run -p bonded_devnet -- e2e --leave-claim
```

3. From `apps/keeper`, with a funded key, run the opt-in test. It must file the claim and then find nothing left to claim:

```bash
SOLANA_RPC_URL=http://127.0.0.1:8899 SOLANA_KEEPER_KEY="$(cat keeper.json)" pnpm exec vitest run test/solana.int.test.ts
```
